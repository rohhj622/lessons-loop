# /wrap — 세션 마무리

## 기록 폴더를 먼저 해석한다

**`$LESSONS_VAULT` 를 그대로 쓰지 않는다.** 그 변수는 세 갈래 중 하나일 뿐이고,
설정 파일로만 정한 사람은 비어 있다. 훅이 쓰는 것과 **같은 해석**을 부른다.

```bash
sh "${CLAUDE_PLUGIN_ROOT}/hooks/py.sh" --quiet paths.py --vault
```

출력이 이 절차에서 쓸 폴더 경로다. 아래에서 `<볼트>` 라고 적은 자리에 넣는다.
**빈 출력이면(종료코드 1) 거기서 멈춘다.** 폴더를 못 찾은 것이므로
`/lessons-loop:configure` 로 설정하라고 사용자에게 말한다. 짐작해서
어딘가에 쓰지 않는다.

---

## 목표

세션이 닫히면 사라질 맥락을 파일로 옮긴다. 배운 것은 `Lessons/` 아래 LSN 노트로
쌓이고, 그것이 다음 세션에서 훅을 통해 자동으로 돌아온다.

세션 서사의 정본은 **커밋 메시지**다. 그 커밋의 diff 가 곧 증거라서, "했다고 적었지만
안 한 일"이 남을 수 없다. 별도의 일지 노트를 만들지 않는다.

## 방법 - 판단은 메인 세션이, 쓰기는 위임한다

메인 세션은 모델을 부를 때마다 그 세션의 대화 전체를 다시 읽는다. `/wrap` 은 긴 세션의
끝에서 돌기 때문에 호출 한 번이 45만~89만 토큰이었고, 실행 한 번에 메인 호출이 20회였다
(2026-10-28 실측, 실행 2건). 검사·색인 명령 자체는 합쳐 몇 초였다. 그래서 대화가 있어야
하는 판단만 메인에 남기고, 정형 쓰기는 새 컨텍스트로 시작하는 에이전트에 한 번에 넘긴다.

### 메인 세션이 하는 일

1. **추가 절차 파일을 먼저 읽는다.** `<볼트>/_Meta/wrap-extra.md` 가 있으면 지금 읽는다.
   없으면 건너뛴다. 그 파일의 `## ` 절 제목에 붙은 표시로 누가 할지 가른다.
   - `[위임]` - 대화 없이 인계 메모만으로 할 수 있는 쓰기. 위임 에이전트에 함께 넘긴다.
   - `[메인]` 또는 표시 없음 - 메인 세션이 한다. 표시 없는 절을 메인으로 두는 것은
     예전 파일이 그대로 돌게 하려는 것이다.
   - 파일에 `위임 에이전트: <이름>` 줄이 있으면 그 에이전트를 부른다. 없으면
     `lessons-loop:lessons-writer` 를 부른다.

   교훈 밖의 기록(프로젝트 진행 상태, 업무 보드 등)은 쓰는 사람마다 달라서 이
   스킬에 넣지 않는다. 그 파일이 이 스킬과 다르게 정한 것(커밋 형식·푸시 여부 등)은
   그 파일을 따른다.

   > 추가 절차를 별도 스킬로 두고 이 스킬을 부르게 했더니, 설명이 같은 두 스킬 중
   > 이쪽이 직접 불려 추가 절차가 세션 94개 중 69개에서 조용히 빠졌다(2026-10-15 실측).
   > 그래서 진입점을 이 스킬 하나로 두고 추가 절차를 파일로 읽는다.

2. **이번 세션에서 실제로 한 일을 대화 기록 기준으로 정리한다.**
   계획했지만 안 한 일과 반드시 갈라 적는다. 이 구분이 없으면 하려던 것이
   한 것으로 기록된다.

3. **교훈 후보를 고른다.** 후보가 되는 것은 이번 세션에서 실제로 틀린 것,
   전제가 뒤집힌 것, 재현 조건이 분명한 함정이다. 잘 된 일은 교훈이 아니다.

   **후보를 고르는 판단은 에이전트가 한다. 사용자에게 고르라고 묻지 않는다.**
   교훈은 사람이 아니라 다음 세션의 에이전트가 읽는 것이라, 무엇이 다시 걸릴지는
   실수를 겪은 쪽이 가장 잘 안다. 전에는 "제목과 한 줄 요약으로 확인받는다"였는데,
   그 질문이 마무리마다 사람에게 분류 결정을 떠넘겼다(2026-10-27). 대신 아래 둘로
   겪지 않은 일이 적히는 것을 막는다.
   - 후보의 근거는 **이 대화의 특정 지점**(틀린 출력, 뒤집힌 전제, 실패한 명령)이어야
     한다. 가리킬 지점이 없으면 후보가 아니다.
   - 7단계 보고에 쓴 교훈의 제목과 근거 지점을 나란히 적는다. 사용자가 거기서
     되돌릴 수 있다. 되돌리기는 파일 삭제와 INDEX 행 삭제 두 줄이다.

4. **인계 메모를 써서 위임 에이전트를 백그라운드로 부른다.** 같은 메시지에서 `[메인]`
   절도 시작한다. 위임 쪽은 대화를 못 보므로 **메모에 없는 것은 쓰지 않는다.**
   교훈 근거는 요약하지 말고 틀린 출력·명령을 한두 줄 그대로 인용한다.

   ```
   절차: <이 스킬의 기본 폴더>/SKILL.md 의 「위임 받은 쪽이 하는 일」 절을 읽고 따른다.
   볼트: <볼트>
   ## 한 일 / 계획했지만 안 한 일
   ## 교훈 후보 - 제목 · impact · 근거 인용 (없으면 "없음")
   ## [위임] 절에 넘길 내용 - 절 제목마다 (예: ISS 변경, PRJ 현재 상태 초안)
   ## 변경 예정 파일
   ```

   위임 에이전트를 부를 수 없는 환경이면 「위임 받은 쪽이 하는 일」을 메인이 직접 한다.

5. **`[메인]` 절을 수행한다.** 사용자에게 물을 것이 생기면 모아 두었다가 **커밋 동의와
   한 번에** 묻는다. 묻는 횟수만큼 사람이 기다린다(실측에서 마무리 시간의 71%가 대기였다).
   커밋 동의를 물을 때는 인계 메모의 변경 예정 파일을 함께 보여 준다.

6. **위임 결과를 확인한다.** 돌아온 변경 파일이 예정과 맞는지, 검사가 `OK` 인지,
   "빠짐" 으로 보고된 것이 있는지 본다. 어긋나면 커밋하기 전에 사용자에게 알린다.
   보고만 믿지 말고 `git status` 로 실제 변경을 센다.

7. **변경한 파일 목록과 각 한 줄 요약을 사용자에게 보고한다.**

8. **동의를 받았으면 커밋한다.** 거절하면 그대로 둔다. 커밋 메시지에 담을 것:

   - 제목: `<주제> - <한 줄 결과>`
   - 왜 했는지 (배경·계기)
   - **실제로** 한 일 - 계획했지만 안 한 일과 구분해서
   - 발견한 것 / 뒤집힌 전제
   - **미완·미검증 항목을 정직하게**
   - 관련 LSN ID

   > 변경이 없는 세션은 기록도 남지 않는다. 억지로 만들지 않는다.

### 위임 받은 쪽이 하는 일

인계 메모만 근거로 쓴다. 메모에 없는 내용이 필요하면 지어내지 말고 "빠짐" 으로 보고한다.
모든 쓰기를 끝낸 뒤 검사와 색인을 **한 번만** 돌린다.

1. **교훈 후보를 `<볼트>/Lessons/LSN-YYYY-MM-DD-NNN.md` 로 쓴다.**
   형식은 `_Meta/schema.md` 의 lesson 절을 따른다. 프론트매터에 `impact`
   (high / medium / low) 를 반드시 넣는다 - 세션 시작 훅이 이 값으로 거른다.

   **같은 실수가 다시 나오면 새 노트를 만들지 않는다.** 쓰기 전에 기존 교훈을 검색해
   보고, 재현이면 기존 노트에 `## 재현` 절을 날짜와 함께 덧붙인다. 조건과 경로가
   다르면 원본을 지우지 않는다.

2. **`<볼트>/Lessons/INDEX.md` 표에 한 줄을 더한다.** 칸 이름은 ID · 제목 · 중요도 ·
   날짜 넷이다. 훅이 머리글 이름으로 칸을 찾으므로 순서는 상관없지만, 이름을
   바꾸면 교훈이 안 붙는다.

   **행을 안 더하면 그 교훈은 회수돼도 제목 없이 나온다.** `_Meta/lint.py` 가
   이걸 잡는다.

   ```
   | [LSN-2026-08-05-001](LSN-2026-08-05-001.md) | 안 불리는 규범은 조용히 낡는다 | high | 2026-08-05 |
   ```

   행은 주제별 묶음(`## ` 2단 제목) 아래에 넣는다. 세션 시작 훅이 대상으로 삼는
   묶음 이름은 **플러그인 설정**의 `상시 주입 묶음 이름` 에 있다.

3. **추가 절차 파일의 `[위임]` 절을 수행한다.** 메모의 해당 절 내용으로만 쓴다.

4. **형식 검사를 돌린다.**

   ```bash
   python "<볼트>/_Meta/lint.py" --selftest
   python "<볼트>/_Meta/lint.py"
   ```

   `--selftest` 를 먼저 돌린다. 빈 결과가 "전건 통과"인지 "검사기 고장"인지는
   이걸로만 갈린다. 교훈만 쓰는 볼트에서도 정상으로 끝나고, 그때는
   `교훈 N/N OK · PRJ 노트 없음(검사 대상 아님)` 이 나온다.

   교훈 검사는 셋을 본다. `impact` 가 있고 어휘 안에 드는지, `id` 가 파일명과
   같은지, `Lessons/INDEX.md` 에 그 행이 있는지다. 셋 다 없으면 회수가 조용히
   빠지거나 제목 없이 나오는 자리다.

   `OK` 가 아니면 이번에 쓴 노트의 위반은 그 자리에서 고친다. 원래 있던 위반은
   고치지 않고 건수만 보고한다.

5. **qmd 를 쓰고 있으면 색인을 갱신한다.** 안 하면 방금 쓴 교훈은 의미검색에
   안 잡힌다. qmd 가 없으면 이 단계는 건너뛴다 - 기본 검색기는 파일을 그때그때
   읽으므로 색인이 없다.

   ```bash
   qmd update && qmd embed
   ```

   바뀐 노트가 몇 건이면 몇 초 안에 끝난다. 끝나면 `qmd collection list` 의 `lessons`
   파일 수가 실제 LSN 개수 + 1(INDEX.md) 과 맞는지 확인한다.

   > 이 갱신이 닷새 밀려 LSN 25건(당시 29%)이 검색에서 통째로 빠진 적이 있다.
   > 그 결과 이미 있는 교훈을 모른 채 반대 내용의 교훈을 새로 쓰는 일이 벌어졌다.
   > SessionEnd 훅이 같은 일을 자동으로 하지만, 그건 이중 방어이지 대체가 아니다.

6. **돌려줄 것:** 바꾼 파일과 한 줄 요약, 검사 결과 줄, 색인 확인 결과, "빠짐" 목록.
   커밋은 하지 않는다. 동의는 메인 세션이 받는다.

## 승격

같은 원인으로 묶이는 노트가 3건 넘게 쌓이면, 그것을 상시 규칙 문서(`CLAUDE.md`)의
한 줄로 올린다. 이 판단은 사람이 한다.

올려도 원본 LSN 은 지우지 않는다 — 조건과 재현 경로가 각각 다르다.

## 제약

- 대화에서 확인되지 않은 성과를 기록하지 않는다. 테스트 실패·미완료는 그대로 적는다.
- 이미 기록이나 git 히스토리에 있는 내용을 중복 기록하지 않는다.
  세션에만 있는 맥락(왜 그렇게 결정했는지, 뭐가 막혔는지)을 우선한다.
